# Baton frontend

React 18 + Vite + TypeScript, Tailwind CSS v4, TanStack Query, React Router, lucide icons.
The screens follow the Figma file "Baton — Complete Product UI/UX" (generated by `design/figma-plugin`),
and the colour and type tokens in `src/index.css` match its "Baton tokens" variables.

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build into dist/
```

## Running against the API

Start the backend first (root README: `docker compose up -d`, then `./mvnw spring-boot:run` with JDK 21,
then `bash demo/load-demo.sh` once to load Project Annapurna). The dev server forwards `/api/*` to
`http://localhost:8080`, so no CORS setup is needed.

In development, `.env.development` sets `VITE_DEMO_PASSWORD`, which shows one-click sign-in buttons for the
seeded personas. Without it, the page shows only the normal email and password form.

## What is live and what is still demo data

Live (`src/data/live.ts`): sign-in and `/me`, projects and members, handovers, sources (list, upload with
authorisation, GitHub re-sync, polling while ingesting), reconstruction (start, latest run, live progress over
SSE), claims (list, detail with evidence, review with optimistic versions, revisions), conflict resolution,
exit-interview answers and skips, timeline, summary and "view as" preview. The approval checks are computed
from live data.

Demo data, clearly labelled in the UI (`src/data/api.ts` + `mock.ts`), because the API does not exist yet:
approving and freezing versions, shares and acknowledgement, the recipient handover pages, users & groups,
and the audit log listing.

```
  data/                live.ts (API hooks), api.ts + mock.ts (demo-only), types
  lib/                 auth (JWT session), http (fetch + SSE), cn()
```
